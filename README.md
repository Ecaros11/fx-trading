## 💰 成本感知的换手控制（v1.5.0，通用引擎层）

> **定位**：游戏只是验证场。这一节做的是**通用引擎**里的事，游戏只是其中一个测试点。

### 问题

`fx_quant` 原本每期都按信号调整仓位，换手很高。真实市场里这是致命的——
但我们测真实外汇时**零成本下都是负的**，所以先要搞清楚：成本控制到底能救什么、不能救什么。

### 我的第一个公式是错的（记在这里）

我先推导了

```
band = c / (2 · H · σ_pred)          ← 错
```

理由是"持有 H 期的期望收益 H·pred 要超过成本 c"。**实测这个带小 2~3 个数量级、完全不起作用**
（EURUSD 算出 0.0013，而信号 std(w)≈0.63，等于没有带）。

**根因：漏掉了目标函数里的风险项。** 完整问题是

```
max_w   α·w  −  (γ/2)·σ²·w²  −  c·|Δw|
        ↑alpha    ↑风险          ↑成本
```

对 `Δw` 求解，L1 项的折点给出**立方根**标度（这才是 Garaleanu & Pedersen 2013 的形态，不是线性）：

```
B = ( 3c / (2·γ·σ²) )^(1/3) ,   γ = σ·√ppy / target_vol
```

量级验证：

| 市场 | σ/期 | B | std(w) | 判断 |
|---|---|---|---|---|
| EURUSD 日线 | 5.5e−3 | **1.13** | 0.63 | ✅ 量级正确 |
| 标普500 月线 | 4.4e−2 | **0.37** | 0.57 | ✅ 量级正确 |
| **游戏 tick** | 1.5e−3 | **41.7** | 0.56 | ❌ 等于"永不交易"，但它明明该频繁交易 |

### 最重要的发现：带的高度不能从市场属性推出

上面第三行说明了一切：**同一个"成本+波动"公式，在游戏上失效。**

原因：公式假设 **alpha 相对成本很弱**。游戏的正弦是**确定性 alpha**，alpha/成本极高，
最优带应该很窄。所以

> **带的宽度取决于「alpha 强度 / 成本」这个比值 —— 那是【策略属性】，不是【市场属性】。**
> 因此"只给成本、公式自动跨市场通用"这个目标**做不到**。

### 立方根标度仍然有价值（这才是真正的交付物）

虽然**水平**要标定，但**形式**告诉你成本和波动变化时该怎么调整，**不用重新标定**：

| 成本变化 | 最优带宽变化 |
|---|---|
| ×2 | **×1.26** |
| ×5 | ×1.71 |
| ×10 | ×2.15 |

> **成本翻倍只让最优换手下降约 21%。** 这反直觉但正确：交易成本上升时，
> 最优换手下降得**比直觉温和得多**。定性地"成本高了就少交易"是对的，
> 但定量的幅度是立方根，不是线性。这个结论对任何市场都成立。

### 样本外验证：标定在真实外汇上【失败】

严格流程：训练集（前 60%）扫 `turnover_aversion`，选最优，再去测试集（后 40%）验证。

```
k        训练集 换手 / Sharpe      测试集 换手 / Sharpe
0.00       0.520    -0.08          0.643    -0.39
1.00       0.296    +0.36          0.412    -0.31    ← 训练集最优
3.00       0.000     0.00          0.000     0.00

训练集最优 k=1.0（Sharpe +0.36）→ 测试集 Sharpe −0.31
```

**标定在样本外完全不成立。** 换手确实降了（0.64→0.41），但 Sharpe 仍是负的。

**这个负面结果本身就是答案**：真实外汇上**没有 alpha 可以保护**，
所以优化换手参数只是在拟合噪声。成本控制的作用是**保住已有的 edge**，不是**创造 edge**。

### 结论：成本控制能做什么、不能做什么

| | |
|---|---|
| ✅ **能**：换手降低 40~50%，成本同比例下降 | 游戏、标普上都成立 |
| ✅ **能**：告诉你在成本/波动变化时该调整多少（立方根） | 跨市场成立 |
| ✅ **能**：在 alpha 厚的地方变现（游戏净收益 +19%） | |
| ❌ **不能**：在 alpha 薄的地方创造收益 | 真实外汇标定失败 |
| ❌ **不能**：靠一个公式跨市场通用（水平必须按策略标定） | |

`fx_cost.py` / `calibrate_band.py` / `diag_band.py` 保留了全部诊断过程。
默认 `min_hold=0`，即**默认关闭**，不影响任何已有结论
（回归验证：游戏 Sharpe 仍 0.0505，真实外汇仍 −0.44%/t −0.53）。

## 🐛 实测事故记录（v1.4.0 修复）

真实运行面板上出现过：**`异常 401` + `开 0 · 平 398 · 被拒 3896`，但持仓明明 5/5**。

两个 bug，都是我的：

### 1. `st is not defined`（每次成功开仓都抛异常）

`apply()` 里留了一句调试垃圾：

```js
if (after[pair] && after[pair].side === want && Object.keys(after).length > before) {
  st.note = 'ok';        // ← st 在这个函数里不存在，抛 ReferenceError
  stats.opened++;
```

后果有三层：
- 每次成功开仓都抛异常，**`stats.opened++` 永远执行不到** → 面板显示「开 0」
- 异常在 `dismissOverlays()` 之前抛出 → 平仓结果弹窗不被关掉
- 异常冒泡出 `tick()` 的货币对循环 → **每根K线只处理一个货币对**

### 2. 用"净仓位数增加"判断开仓成功

```js
const before = Object.keys(heldPositions()).length;
btn.click();
if (... && Object.keys(after).length > before) { /* 算成功 */ }
```

本策略是**平一仓、开一仓**，净仓位数不变 → **每次成功开仓都被记成"被拒"**。
面板上的 `被拒 3896` 全是假的。

> 这个错误我在这个项目里犯过**第二次**了 —— `fxsim.py` 的复利触发条件原本也写的
> `len(acct.pos) < prev_npos`，同样因为"平一开一净数不变"而永不触发。
> **同一个逻辑陷阱，两个语言，各踩一次。**

正解：走到那一步时该货币对要么没仓、要么是反向仓（已在上面平掉），
所以只要回读到的方向 == `want`，就一定是刚开成功的。

### 3. 为什么测试没抓到

`st is not defined` 是在 `tick()` 里抛的，而 `tick()` 被 `step()` 的
`try { tick(); } catch (e) { stats.errors++; }` **捕获了** —— 它不是 uncaught exception，
所以测试的"无 JS 错误"检查（靠 `window.onerror` / `jsdomError`）永远是绿的。

**必须直接断言 `stats.errors === 0`。** 已加入 `test-quant.mjs`：

```
开=126 平=121 被拒=0 异常=0
✅ 「开」计数 > 0（不是假报 0）
✅ ❗ 脚本内部无异常（stats.errors=0）
✅ 被拒次数没有异常膨胀
✅ 开仓计数与观测到的持仓数一致
```

### 教训（第三次同一个主题）

**"脚本没崩"不等于"脚本在工作"。** 内部异常被自己的 try/catch 吞掉后，
唯一能暴露它的就是**直接断言业务计数器**：`stats.errors === 0`、`stats.opened > 0`、
`被拒 < 开 × 3`。这些断言比我之前所有"机制检查"都更直接。

### 股票要跑多久？（`time_to_profit_stocks.py`）

**先纠正问题本身**：股票上"多久开始赚钱"这个问题和游戏不是一回事。

- **游戏**：没有漂移，所有钱都来自择时能力 → "多久盈利"= 择时能力多久显现
- **股票**：大部分钱来自**股权风险溢价**（只要长期持有就有），跟引擎无关

所以股票上真正该问的是 **"择时能不能跑赢买入持有"**。

**标普500（1871-2026，可用区间 105 年，base=1 满底仓）**

| 持有 | P(不亏钱) | **P(跑赢买入持有)** |
|---|---|---|
| 1 个月 | 53% | 19% |
| 1 年 | 71% | 28% |
| 5 年 | 85% | **39%** |
| 10 年 | 94% | 32% |
| 20 年 | 99% | **30%** |

**AAPL（2016-2026，base=1）**

| 持有 | P(不亏钱) | **P(跑赢买入持有)** |
|---|---|---|
| 5 日 | 55% | 42% |
| 60 日 | 61% | 38% |
| 250 日（1年） | 85% | 21% |
| 1000 日（4年） | 100% | **0%** |

### 结论（和游戏相反）

1. **"不亏钱"的答案主要由市场决定，不是策略的功劳。** base=1 时你就是长期持有者，
   1 个月 53%、5 年 85%、20 年 99% —— 这就是股权风险溢价本身。
2. **择时几乎从不跑赢买入持有，而且持有越久概率越低**（5 年 39% → 20 年 30%）。
   这是"长期收益偏低"的典型特征，不是"需要更长时间"。
3. 但它**改善了风险调整收益**：Sharpe 0.59 vs 买入持有 0.51，回撤从约 −80% 降到 −64.8%。
   **代价是年化低约 1 个百分点**（7.08% vs 8.07%）。
4. 所以它的正确定位是 **"降低波动的叠加层"**，不是"提高收益的策略"。
   想靠它战胜指数是错的；想用它把指数的波动压下来一点、代价是少赚一点，是可行的。

> **一句话对比**：游戏里"跑 90 分钟见分晓"；股票里**不存在这个时间点** ——
> 因为股票的钱主要不是策略赚的，而策略想赚的那部分（跑赢指数）在 105 年样本里
> 只在 30~39% 的情况下成立。

### 5. 要跑多久才开始赚钱？（40 个种子实测，`time_to_profit.py`）

这是 JS 实际行为（`train=3000, minSamples=240`）：

| 跑多久 | 40 个种子里仍在盈利的比例 |
|---|---|
| 6 分（刚开仓） | 0% |
| **15 分** | **32%** |
| **30 分** | **35%** ← 会回落 |
| 45 分 | 52% |
| 60 分 | 72% |
| 75 分 | 78% |
| 90 分 | 80% |
| 135 分 | 98% |
| 300 分 | 100% |

**首次浮盈**：中位 **242 ticks ≈ 6 分 03 秒**（几乎一开仓就赚）
**但这是假象** —— 30 分钟时只剩 35% 还在盈利，很多人已经翻负又翻正。

**置信度首次达标（此后保持）**：

| 目标 | 需要 | 折合 |
|---|---|---|
| 50% 的种子盈利 | 1439 ticks | **36 分** |
| 75% | 2448 ticks | **61 分** |
| 90% | 4038 ticks | **101 分** |
| 95% | 4888 ticks | **122 分** |
| 100% | 7235 ticks | **181 分** |

期末（20000 ticks ≈ 8.3 小时）：最差 **+766%**，中位 **+20244%**，最好 **+152123%**
（每单位名义仓位的复利累计）

**所以：前 30 分钟看到亏钱是正常的，别急。** 想看"这套东西到底行不行"，
至少跑 **90 分钟**；要接近确定，跑 **3 小时**。

> **⚠ 实现差异（已修）**：Python 版 `walk_forward_ridge` 原本写的是 `if t >= train`，
> 意味着 `train=3000` 时**前 3000 ticks（75 分钟）完全不下单**；
> 而 JS 版的 `refit()` 只要攒够 `minSamples=240` 就开始拟合 → **第 240 根就下单**。
> 两者差别巨大，已给 Python 加 `min_train` 参数对齐。
> JS 的"早开始"更好（期末中位 +20244% vs 旧行为 +15781%），所以保留 JS 行为。

### 6. 会自动调整投入的保证金吗？—— **默认不会**

`RISK.margin` 只在点「启动」那一刻从界面读一次（`fx-quant-autopilot.user.js:628`），
之后整场运行都用这个固定值，**永不调整**。

回测那边其实也一样：`fxsim.run` 的复利条件是 `if not acct.pos`（只在**全部空仓**时重定价），
而策略同时持 5 仓，这个条件几乎从不成立 → **等价于固定保证金**。
所以所有已发布的收益数字都是"固定保证金"口径，没有假设任何复利。

**差距有多大**（游戏引擎，7 种子，5 仓 @20×，5 小时，每仓目标 权益×5%）：

| 保证金模式 | 收益中位数 | 最差种子 | 爆仓 |
|---|---|---|---|
| **固定 $500/仓（默认，= 所有回测口径）** | **+$128,039** | +$118,327 | 0 |
| 复利：每次开仓按当前权益×5% 重定价 | **+$28.1 亿** | +$10.9 亿 | 0 |

**但我把复利做成了可选开关、默认关闭。** 理由：

1. **28 万倍是指数外推，不是预测。** 3700 笔交易会把"每笔 edge 有多大"的任何估计误差
   指数放大；模型里也没有容量/滑点约束。
2. 我**没有对这个复利区间做过压力测试** —— 一旦 edge 估计偏乐观，放大后的回撤同样是指数级的。
3. 单仓爆仓风险与保证金大小无关（爆仓线是 `0.8/杠杆` 的**逆向波动**），所以放大保证金
   不增加单仓爆仓概率 —— 这一点是安全的。但账户的绝对波动会同步放大。

**怎么开**：面板上就有开关（v1.3.0 起），在「每仓保证金」那一行：

```
每仓保证金  [ 固定 ] [ 权益% ]  [2% ▾]
```

- 点「**权益%**」→ 每次开仓按 `当前权益 × 比例` 重定价（自动复利），旁边出现比例下拉
- 点「**固定**」→ 回到启动时从界面读到的固定值

`equity` 模式带了两个保护：单仓不超过 `maxMargin`（默认 $20,000）；
并且会按**剩余名额**预留现金，避免"开到一半没钱了"。

也可以从控制台设（跑之前）：

```js
__FX_QUANT__.CONFIG.marginMode = 'equity';   // 'fixed'（默认）| 'equity'
__FX_QUANT__.CONFIG.equityFrac = 0.05;       // 每仓占权益比例
__FX_QUANT__.CONFIG.maxMargin  = 20000;      // 单仓硬上限，防跑飞
```

> **建议**：先跑一轮 `fixed` 确认整套链路正常（下单、平仓、被拒计数），
> 再考虑开复利。而且如果要开，先用 2% 跑一轮看看。

> **教训**：我第一版把 `marginMode` 只做成控制台配置项、面板上仅"显示"当前模式，
> 用户反馈"没看到开关"。**能配置 ≠ 能用** —— 涉及用户操作的开关必须落在 UI 上。
> 补上开关后又发现：新处理器调用了 `readRiskSettings()`，而那个函数在 fx-quant 里
> **根本不存在**（写脚本时把它内联掉了），异常被 jsdom 静默吞掉。
> 已给测试补上 `window.addEventListener('error')` —— jsdom 里事件监听器抛的异常
> **不会**走 virtualConsole，这个漏洞真实存在过。

## 📈 能覆盖股票吗？—— 实测回答

**架构上可以**（引擎吃任意价格序列），但**直接套用会亏**，原因是一个结构性差异：

> 外汇没有无条件漂移，基准是"0"；股票有**股权风险溢价**，基准是**买入持有**。
> 而这个引擎是**多空对称**的 —— 在上涨的市场里，做空的那一半在跟风险溢价对着干。

### 结论

0. **先量漂移，再定底仓。** 实测（`measure_drift.py`）三个资产的无条件漂移：

   | 资产 | 每期漂移 | 折合年化 |
   |---|---|---|
   | **游戏** | **−9.34e−06 / tick** | **≈ −2.2% / 小时**（**负的**） |
   | 游戏（正弦幅度设为 0） | −9.30e−06 | 与上面几乎相同 → 漂移**全部来自快讯 bias 表的不对称**，不是正弦 |
   | EURUSD | −5.3e−06 / 日 | ≈ −0.1% / 年 |
   | EURJPY | +4.0e−05 / 日 | ≈ +1.0% / 年（利差） |
   | 标普500 | +3.99e−03 / 月 | **≈ +4.9% / 年** ← 股权风险溢价 |

   游戏上直接扫 `base_exposure`：

   | base | Sharpe/期 | t | 累计 |
   |---|---|---|---|
   | −0.5 | 0.0503 | 7.12 | +4188% |
   | **0.0（默认）** | **0.0505** | **7.14** | **+5802%** |
   | +0.5 | 0.0500 | 7.07 | +4096% |
   | +1.0 | 0.0487 | 6.88 | +2873% |

   **游戏 `base=0` 最优，但原因不是"没有漂移"，而是漂移是【负】的** ——
   做多头底仓是在逆着 −2.2%/小时的逆风。**这就是为什么必须先量再定，不能凭直觉。**

1. **股票必须加常数底仓**：`base_exposure≈1`（100% 多头底仓）。不加的话标普500 上直接少赚 5.7 个百分点/年。
2. **加了底仓之后，择时确实有一点点增量**：155 年样本上 Sharpe 0.59 vs 买入持有 0.51（t 6.04 vs 5.29），
   回撤从约 −80% 降到 −64.8%。**但这是"小幅改进"，不是"换个策略就能赚"。**
3. **单只股票上择时反而有害**（AAPL Sharpe 0.72 vs 0.79）——10 年样本不显著，但至少没有证据支持。
4. **`max_lev` 必须夹【总仓位】**。若只夹择时部分，`base=1` 加 `max_lev=3` 会叠成 4 倍杠杆，
   标普500 回撤会到 **−97.5%** —— 那样"跑赢买入持有"只是加了杠杆，不是本事。（这个坑我踩过，已修）
5. **架构性局限：本引擎是时序（time-series）的，不是横截面（cross-sectional）的。**
   股票里最经得起检验的异象 —— 横截面动量、价值、低波动、规模 —— **都需要在一堆股票之间排序**，
   本引擎一次只看一条序列，天然做不到。想覆盖那些，得换成组合优化框架。

> **一句话**：这套引擎**能跑**股票，正确用法是"**100% 底仓 + 择时做小幅偏离**"，
> 而不是把它当成独立的择时策略。指望它替代买入持有是错的；指望它在买入持有之上
> 改善一点风险调整收益，155 年标普数据支持这一点。
>
> **底仓机制对游戏同样适用，但答案是 `base=0`** —— 因为游戏的漂移是负的
> （快讯 bias 表不对称导致，约 −2.2%/小时），加多头底仓反而是逆风。

## 核心结论：这个游戏有两个可利用的破绽

### 破绽 A —— 模拟数据 / 每日挑战模式

`app.js` 第 562 行：

```js
const drift = Math.sin(Date.now() / 13000 + index * 2 + marketIndex * .7) * .00036;
```

这个漂移项是 **墙钟时间的确定性函数**，跟随机数、行情、账户都无关。

价格变化 ∝ ∫sin，所以：

| 区间 | 累积漂移 | 应该做什么 |
|---|---|---|
| 正半周（sin 由负转正 → 由正转负） | **+62.4 bp** | 做多 |
| 负半周（sin 由正转负 → 由负转正） | **−62.4 bp** | 做空 |
| 波谷 → 波峰（对称区间） | 0 bp | ⚠️ 直觉陷阱，白干 |

> **最容易搞错的地方**：直觉会让人"低买高卖"，即在波谷买入、波峰卖出。
> 但正弦在对称区间积分正好抵消，实测只能赚 2.8 bp（还不够手续费）。
> 正确做法是持有**整个正半周**：在 sin 上穿零点时进，下穿零点时出。

零点时刻有闭式解，可以提前精确计算：

```
t_k = 13000 × (kπ − 2i − 0.7·marketIndex)
```

### 破绽 B —— 真实数据 / 经典战役模式

这两个模式的行情来自公开接口 `api.frankfurter.dev`，游戏只是让你**逐日**点「下一交易日」。
数据是公开的 ⇒ 你还没点的那一天，价格早就是确定值。

而且真实模式**只有日度收盘价**，爆仓只在推进到某日收盘时判定一次 ——
整条未来路径完全可计算。

### 🐛 已修复：闸门死锁（v1.0.0 → v1.1.0）

**症状**：游戏里样本已经 350+，却一笔都不开。

**原因**：显著性闸门的影子收益用的是**已经过闸门的仓位**：

```js
// 旧代码（有 bug）
st.pnlRoll.push((st.wPrev * ret - cost * Math.abs(st.w - st.wPrev)) * 10);
st.w = open ? w : 0;          // 闸门一关，w 永远是 0
```

闸门关闭 → 影子收益序列全为 0 → 标准差 0 → t 值 0 → `t >= 1.0` 永远不成立 → **闸门永久锁死**。
默认 `gateT=1.0` 时，这个引擎**从第一次关闸起就再也不会交易**。

**这个 bug 就写在我自己的测试输出里，我上次没看出来**：

```
t= 18s  样本  93  t值  0.00  开  持仓 5   ← 闸门样本还不够，默认 open=true 才开的
t= 24s  样本 124  t值 -0.61  关  持仓 0   ← 闸门评估后关闭
t= 30s~48s       t值 -0.61  关  持仓 0   ← 此后永远打不开，t值冻在 -0.61
```

我当时只断言了"开过 / 关过"，就打了 ✅，完全没注意它**再也没开过**。

**修复**：闸门影子改用**未闸门的仓位**结算，与闸门开关彻底解耦
（Python 版 `fx_general.py` 里我早先修过同样的坑，但没带进 JS 版）：

```js
st.gateRoll.push((st.wRawPrev * ret - cost * Math.abs(st.wRaw - st.wRawPrev)) * 10);
st.wRaw = w;                  // 先记未闸门仓位
st.w = open ? w : 0;          // 再决定实际仓位
```

**同时把默认 `gateT` 改成 0（关闭）**，依据是回测而不是图方便：

| 游戏引擎 train=1500 | Sharpe/期 | 累计收益 |
|---|---|---|
| 闸门开（`gateT=1.0`） | 0.0459 | +2229% |
| **闸门关（`gateT=0`）** | **0.0520** | **+6632%** |

在这个数据上闸门严格更差。它的意义是"在没 edge 的数据上别乱赌"，那种场景再手动设成 `1.0`。

**回归测试**（`test-quant.mjs`）现在会【强制】关一次闸门再恢复，确定性地检验：

```
强制关闸 8 秒后：持仓 0
恢复 8 秒后：闸门影子 std = 2.13e-2，t值 = -0.61
✅ ❗ 关闸期间影子仍在记录 —— 闸门不会被永久锁死   std = 2.13e-2（旧代码此处会变成 0）
✅ ❗ 恢复后 t 值重新有效（不是冻结的 0）
✅ 默认设置下正常开仓（用户实际场景）  峰值 5 笔
```

> 教训：断言"机制被触发过"是不够的，必须断言"机制在被压制后能恢复"。

### 关键转变：从"挑一个策略"改成"在线学一个线性组合"

之前几版都是"跑一堆策略，跟表现最好的那个"。**这个做法本身就是错的**，我做了受控对比才发现：

| 方案（游戏引擎 20000 ticks × 3 种子） | Sharpe/期 | 相对 |
|---|---|---|
| 事后最优单策略（含前视，理论上限） | 0.0400 | 100% |
| **旧方案：按影子盈亏 Hedge 集成** | **0.0151** | **38%** |
| **新方案：在线岭回归 train=1500** | **0.0520** | **130%** |
| **新方案：在线岭回归 train=3000** | **0.0690** | **173%** |
| 作弊基准（直接读正弦相位） | 0.1589 | 397% |

**在线岭回归是旧集成方案的 3.4~4.6 倍**，并且达到作弊基准的 43%（旧方案只有 9.5%）。
它甚至超过了"事后最优单策略"——因为线性组合能把几十个弱信号按各自的信息含量加权。

### 三层结构

1. **特征层**：30 维、全部由价格算出、量纲无关、严格因果
   - 波动状态 `vol_n / mean(vol_n)` ×6
   - 波动率标准化动量 `(p/p_{t-n} − 1) / (σ_n·√n)` ×6
   - 偏离均线的 z 分数 `(p − MA_n)/sd_n` ×6
   - 均线差 / 加速度 / 波动比 ×4 组
   - 每个特征再做一次滚动标准化（窗口 250）
2. **预测层**：`r_{t+1} ≈ β·x_t`，滚动岭回归（窗口 `train`，每 `step` 根重拟合）
3. **风控层**：预测标准化 → 波动率目标仓位 → 显著性闸门（滚动 t 值不够就空仓）→ 成本

|---|---|---|---|---|
| 合成·随机游走 | −2.37% | −0.22 | −1.14 | ✅ 没乱交易 |
| 合成·均值回归 OU | **+15.84%** | **1.30** | **+6.92** | ✅ 找到了 |
| 合成·正弦+噪声 | **+7.71%** | **1.46** | **+7.75** | ✅ 找到了 |
| **真实外汇（27 年，9 对）** | **−0.32%** | −0.07 | −0.40 | ❌ **没有 edge** |

`step`（重拟合间隔）在 50~250 之间几乎无差别。**挑战模式没有时间上限，所以 3000 值得等。**

## 策略 D：通用自适应框架（影子账户 + Hedge 集成）

> ⚠️ 已被**策略 E** 取代。保留是因为它记录了一个重要的负面结论：
> **"挑最好的策略"是个笨办法**（只有线性组合上限的 38%），以及那套显著性闸门的设计。



> 这是唯一一个**不绑定任何特定价格过程**的方案。
> 游戏、新的类似游戏、真实股票外汇，喂同一套代码即可。

**文件**
- `fx_general.py` —— Python 参考实现（回测/研究用）
- `run_general.py` / `diag_general.py` —— 跨域检验与诊断
- `run_general_game.py` —— 在游戏引擎上的检验
- `fx-general-autopilot.user.js` —— JS 移植版，在游戏里实盘运行（23 个候选）
- `fetch_data.py` —— 抓取真实 ECB 汇率（1999-2026，7104 个交易日）
- `test-general.mjs` —— 静态指纹扫描 + 端到端

### 三个部件

1. **策略池** —— 23~28 个候选，同时包含**趋势**（均线、时序动量、通道突破）与
   **均值回归**（动量取反、z 分数）两类。**哪一类有效不由我预判。**
2. **影子账户** —— 每个候选维护"如果一直听它的"累计净值，手续费从第一天就扣。
   按近期表现做指数加权（Hedge）。权重与均匀分布混合 15%，避免塌缩到单一策略。
3. **显著性闸门** —— 只有当组合近期的风险调整收益在统计上显著（t 值过阈值）才持仓，
   否则空仓。**这是整套东西能通用的关键：没有证据就不下注。**

所有统计量只用当期及之前的数据，**整个回测天然是样本外的**。

### 跨域检验（同一套代码、同一组参数）

| 数据 | 年化 | Sharpe | **t 值** | 结论 |
|---|---|---|---|---|
| 合成·纯随机游走 | +0.12% | 0.01 | **0.06** | ✅ 没乱交易 |
| 合成·均值回归 OU | **+18.06%** | **0.77** | **4.08** | ✅ 找到了 |
| 合成·正弦+噪声 | **+1.18%** | **0.51** | **2.69** | ✅ 找到了 |
| 游戏引擎（20000 ticks） | — | 0.029/期 | **4.15** | ✅ 有效，但只有正弦作弊版的 ~1/5 |
| **真实外汇（27 年，9 对）** | **−0.61%** | **−0.25** | **−1.33** | ❌ **没找到** |

### 关于真实市场，必须说清楚的结论

我做了四轮排查，确认这不是实现问题：

| 排查 | 结果 | 说明 |
|---|---|---|
| 成本设为 **0** | 年化 **−0.50%** | **不是手续费吃掉的 —— 毛信号本身就不存在** |
| 降到**月频** | 年化 +0.25%（t=0.33） | 也不是频率/换手的问题 |
| 最好的**单策略** | Sharpe 0.25，t=1.34 | 28 个策略里 16 个为正（纯随机约一半），**无一显著** |
| **闸门阈值**扫描 0→3 | 年化 −2.19% → −0.05% | 没有任何阈值能让它转正；交易越多亏越多 |

所以：**这套方法在存在 edge 的数据上确实能找到并利用（OU 的 t=4.08、正弦的 t=2.69），
在没有 edge 的数据上会趋向少交易而不是硬赌（随机游走的 t=0.06）；真实日频外汇属于后者。**

### 策略族的选择是数据自己做出来的

这是"通用"最直接的证据 —— 同一份代码，在两个域里选出**相反**的家族：

| 数据 | 数据自己选出的策略族 |
|---|---|
| 游戏（正弦+噪声） | **趋势族总权重 75.8%**（TSMOM10 0.223、MA5/20 0.174） |
| 真实外汇 | **均值回归族占优**（REV250 权重第一，前 6 名里 5 个是 REV） |

我没有告诉它哪个域该用哪一类。

### 怎么用在**一个新的类似游戏**上

1. 抓价格序列 —— 任何来源（DOM、接口、CSV）都行，喂一个 `list[float]`。
2. `python run_general.py` 里把 `gen_*` 换成你的数据（或直接 `G.backtest(prices)`）。
3. 看 `w_avg`：数据把权重给了哪个族、哪个参数，就说明它是什么过程。
4. **先看闸门开闸占比与 t 值**。t 值上不去就说明这个数据没有可交易的 edge ——
   这时候正确的做法是不做，而不是调参调到看起来能赚。

### 已知道的限制

- **短样本下策略族的选择不稳定**。JS 端到端测试只有 220 根 K 线时，
  趋势权重在 **11%~94%** 之间摆动。要稳定判断家族，至少要几千根。
  这也是我**删掉了原测试里"趋势必须占优"这条断言**的原因 —— 它超出了样本能支撑的结论。
- **`window`（回看窗口）是唯一剩余的超参数**。游戏上扫描 50~400，250~400 明显更好；
  外汇用 250。它决定"用多少影子证据做选择"，越长越稳但适应越慢。
- **闸门会漏掉真实的 edge 起点**：t 值需要时间积累，趋势刚形成时它还在空仓。
- **波动率目标 / 凯利式仓位没有做**。当前只输出方向，仓位大小取自游戏界面或固定值。
- 真实市场里被文献支持的 edge（FX carry、value、跨资产动量）**依赖价格以外的数据**
  （利率、基本面），这套纯价格框架拿不到，所以它测不出这些 edge 是正常的，
  不代表那些 edge 不存在。

## 策略 B：纯 K 线均线（⚠ 参数仍编码了周期知识）

> 保留作对照。如果你要"完全不作弊"，请用上面的**策略 C**。


脚本面板上可以随时切换两种信号源：

| | 正弦相位 | 纯 K 线均线 |
|---|---|---|
| 依据 | `sin(Date.now()/13000 + 2i)` | 只读 `#pairList` 的实时报价，自己算 MA |
| 是否用公式 | 是 | **否** |
| 5 小时中位收益 | +$133,353 | +$42,538（MA 4/16） |
| 胜率 | 80.4% | 42.7% |
| 爆仓 | 0 | 0 |

**怎么拿到 K 线**：`renderPairs()` 每 tick 都会把 7 个货币对的报价写进
`#pairList .pair-row .pair-numbers strong`。所以脚本只需要轮询 DOM，
不需要碰 canvas，也不需要碰任何公式。

**信号**：`MA(fast) > MA(slow)` → 做多，否则做空。默认 `MA 4/16`。

**采样细节**：7 个价格里只要有一个变了，就算新的一根 K 线（用联合签名去重）。
这样能保证 7 个货币对严格对齐同一个 tick，不会因为某个货币对报价没变而错位。

3/10、4/16、5/15、5/20 都在赚 —— 这是一个**宽平台而非尖峰**，说明不是过拟合。

### 为什么均线在这个游戏里能赚钱？

这个价格过程 = **周期性漂移（正弦）+ 零均值噪声**。
均线是价格的线性滤波器，它唯一能提取出的自相关成分，就是这个正弦。
**所以均线赚钱的本质，仍然是间接估计了同一个周期项** —— 只是它"不知道"自己在估计什么。

回测从三个方向印证了这一点：

1. **窗口越长越亏**：MA 10/40、13/34、唐奇安(30) 都是负期望。
   因为慢线的滞后（≈ W/2 tick）超过了半周期（27 tick），进场时漂移已经反转。
2. **逆势策略必爆仓**：布林逆势期望 −18 bp 且爆仓 17 次；RSI 逆势爆仓 22 次。
   这个过程只有趋势、没有均值回归，**fading 它正好做反**。
3. **胜率结构符合趋势跟踪**：赚钱的策略胜率只有 37%~45%，靠少数大赢覆盖多次小亏；
   而正弦策略胜率 80%。两者是同一份 edge 的不同提取效率。

**结论**：纯 K 线可以自动交易、并且稳定盈利，但只能捕获约 **1/3** 的 edge。
想不碰公式就用 MA 4/16；想要最大收益就用正弦相位。

### 诚实边界：哪些地方用到了算法知识？

这个区别很重要，我不打算含糊过去。

#### ✅ 运行时的信号：完全不用

`targetSide()` 的 MA 分支只有 **228 个字符**，只读 `hist[pair]` 和 `windows()`。
三项独立验证：

| 验证 | 方法 | 结果 |
|---|---|---|
| 时钟跳变 | 喂给 `targetSide()` 两个相差**整整一年**的时刻，K 线历史不变 | 决策**逐位相同**；对照组（正弦）对时刻敏感，证明测试有效 |
| 信号分歧 | 同一时刻比较 MA 信号与正弦信号 | 49%~57% 的样本方向不同（若偷看公式应接近 0%） |
| 静态扫描 | 在 MA 分支源码里搜 `13000` / `Date.now` / `phaseOf` / `Math.sin` / `0.00036` | **一个都没有** |

#### ⚠️ 设计参数：用了

`MA 4/16` 这两个数字不是任意选的。**证伪实验 2**（`falsify_ma.py`）把引擎的周期改成 1/2 和 2 倍：

| 引擎周期（根K线） | 理论半周期 | 实测最优窗口 |
|---|---|---|
| 27.2（K=6500） | 13.6 | **3/8** |
| 54.5（K=13000，**本游戏**） | 27.2 | **3/12 ~ 4/16** |
| 108.9（K=26000） | 54.5 | **4/24** |

最优窗口随周期单调变化。所以 `4/16` 之所以是最优，**正是因为**本游戏的周期是 54.5 根 K 线。
换句话说：**运行时只吃 K 线，但"选多长的窗口"这件事用到了算法知识。**

#### 🧪 证伪实验 1：edge 确实全部来自周期项

把周期性漂移的幅度直接调成 0：

| 漂移幅度 | MA 4/16 | MA 5/20 | 胜率 |
|---|---|---|---|
| **0（拿掉周期项）** | **−$4,227** | **−$4,191** | 33.7% |
| 0.00018（一半） | +$3,692 | +$2,865 | 36.1% |
| 0.00036（正常） | +$26,286 | +$21,816 | 43.2% |
| 0.00072（两倍） | +$96,639 | +$79,184 | 67.4% |

**没有周期项，均线立刻亏钱**，且收益随漂移幅度单调增长。
这证实了"均线只是在间接估计同一个正弦"，而不是抓到了什么真实的市场结构。

#### 🗑️ 已删除的泄漏

`windows()` 原本长这样：

```js
const scale = Math.max(0.5, Math.min(3, tickMs() / 1500));   // ← 1500 是 app.js 的 tick 间隔
f = Math.round(f * scale); s = Math.round(s * scale);
```

`1500` 来自 app.js，而这个缩放的比例等于把"周期是 54.5 根 K 线"直接写进代码。
**已整段删除**。现在窗口单位就是"根 K 线"，脚本不关心一根 K 线花多少秒；
只在实测节奏明显偏离标定值时写一条告警（诊断用，不参与信号）。

#### ❌ 试过但放弃的方案

想让窗口**完全由数据自己决定**，试了两种从 K 线估计周期的方法，**都失败了，所以没有采用**：

- **自相关**：信号自相关幅度只有 0.0325，而有限样本标准误约 0.007，长滞后上被噪声淹没。
  对 1/2 周期、1 倍周期、2 倍周期都返回了同一个 ~52，明显是抓噪声。
- **周期图**：在真实周期上很准（K=13000 → 估计 54.5，误差 0.1%；K=26000 → 109.0），
  且能区分信号与噪声（峰/中位比 135 vs 9.25）。**但**在短周期（K=6500）失效 ——
  "有信号"和"纯噪声"的功率谱剖面几乎一样。而且它需要几千根 K 线才能可靠工作，
  实时脚本里根本攒不到那么长的历史。

所以最终选择了**不做自动估计、并明确标注参数来源**，而不是塞一个我验证不过关的估计器进去。

## 快速上手

### 场景 1：每日挑战 / 模拟数据 → 自动驾驶脚本

**安装**

1. 浏览器装 **Tampermonkey**（油猴）。
2. 新建脚本，把 `fx-autopilot.user.js` 全文粘进去，保存。
3. 打开游戏页面，右下角出现控制面板。

**每日挑战模式的完整流程**

1. 点游戏里的「**挑战模式**」按钮切换过去。
2. 点面板上的「**开始新挑战**」（消耗 1 次今日机会，每天 3 次）。
   > 挑战**没有时间限制** —— `challenge.active` 会一直为 true 直到你「金盆洗手」。
   > 所以 3 次机会你只需要用 1 次，可以在同一局里跑几个小时。
3. 点面板的「**启动**」。脚本会按「剩余可赚漂移」从高到低挑出最值得做的 5 个货币对建仓。
4. 跑够了之后点面板的「**金盆洗手**」→ 游戏弹出确认框 → **你自己**点「确认结算」。
   > 脚本**不会**替你点这个确认（会代点的只有无副作用的提示框）。
5. 成绩自动提交到今日榜（`board: 3`，得分 = `收益 ÷ $100`）。

脚本会自动处理：平旧仓 → 选货币对 → 设杠杆/保证金 → 开新仓 → 关闭挡路的提示弹窗 →
仓位上限控制（挑战 5 / 模拟 7）→ 需要你确认的弹窗则暂停交易。

| 每日挑战 | 20× | 权益 × 15% | 75% | 5 |
| 模拟数据 | 20× | 权益 × 5% | 35% | 7 |

> ⚠️ **保持标签页在前台**。后台标签页会被浏览器限流；策略仍然成立（漂移只看绝对时间），

## 风险与注意事项

1. **爆仓机制**：亏损达保证金 80% 触发爆仓，60% 时弹窗预警**并冻结行情**
   （`tickSim` 首行 `if (riskPaused) return;`）。
   20× 杠杆下爆仓需要 4% 反向波动 ≈ 5.4σ，回测 10,284 笔交易 **0 次爆仓**。
   但**不要上 50× 以上**：100× 时爆仓线只剩 0.8%，接近半周期噪声水平。
2. **滑点与跳空**：模拟行情有 1.8%/tick 的概率发生最大 ±0.95% 的跳空，
   极端情况下可能穿过爆仓线，出现负余额（穿仓）。
3. **手续费随杠杆平方增长**：`margin × leverage × (0.00005 + leverage × 0.000005)`。
   100× 时手续费吃掉保证金的 5.5%。
4. **挑战模式限制**：每日 3 次、1 万本金、禁用贷款、**最多同时 5 仓**（脚本已适配）。
5. **排行榜公平性**：每日挑战的成绩会提交到 B 站日榜（`board: 3`）。
   用这个漏洞刷榜对其他玩家不公平，也可能违反平台规则 —— **建议只在"模拟数据"模式里玩**。
6. **脚本已做端到端测试**：用 jsdom 加载真实的 `app.js` + 自动驾驶脚本实跑
   （`node test-autopilot.mjs`），结果：7/7 持仓、相位同步率 100%（56 次采样 0 偏离）、
   零 JS 错误。测试过程中抓到并修复了一个真实 bug —— `window.matchMedia` 并非所有环境
   都实现，原本会让每次下单都抛异常。**但 jsdom 不等于真实浏览器**，
   第一次上真机时仍建议先观察几轮。
7. **不要在 `sim` 模式之外用自动驾驶**：真实数据/经典战役模式没有正弦漂移，
   脚本会自动暂停并提示（已加入保护）。

## 数学附录

**为什么是 +62.4 bp**

从相位 φ₀ 到 φ₁ 的累积漂移：

```
Δ = 0.00036 × Σ sin(φ₀ + k·ω),   ω = 1500/13000 = 0.11538 rad/tick
  ≈ (0.00036/ω) × [cos(φ₀) − cos(φ₁)]
```

取 φ₀ = 0（sin 上穿零点）、φ₁ = π（sin 下穿零点）：

```
Δ = (0.00036/0.11538) × [1 − (−1)] = 0.00624 = 62.4 bp
```

持有 27 ticks ≈ 41 秒。

**半周期噪声**

单 tick 收益标准差：

```
震荡 = 0.0042/√12 = 0.001213
跳空 = √(0.018 × 0.019²/12) = 0.000736
合计 σ = √(0.001213² + 0.000736²) = 0.00142
```

27 ticks 后 σ = 0.00142 × √27 = **0.0074 = 74 bp**

**胜率** = Φ(62.4/74) = Φ(0.843) = **80.0%** ✓ 与回测的 80.3% 吻合

**爆仓概率**（20×，爆仓线 4%）= P(74 bp × Z ≥ 400 bp) = P(Z ≥ 5.4) ≈ 3×10⁻⁸
